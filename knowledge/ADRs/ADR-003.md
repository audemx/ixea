# ADR-003: Estrategia de Autoconsumo de Metadatos mediante Generación Automática de Modelos y Schemas JSON

## Contexto
Con una base de datos amplia (>50 tablas) y en constante evolución[cite: 5], mantener manualmente los archivos de modelos PHP Eloquent y la documentación de la estructura del esquema es propenso a errores humanos y desincronizaciones entre el esquema SQL real y la capa de aplicación[cite: 2].

## Decisión
Se decide automatizar el flujo de construcción e inspección del sistema mediante la creación de scripts de infraestructura de código[cite: 2]:

1. **`gen-models.php`**: Inspecciona las tablas, tipos de columnas y restricciones en MariaDB/MySQL para autogenerar las clases de modelos Eloquent en `src/app/db/models/`[cite: 2, 4].
2. **`gen-schema-json.php`**: Exporta una representación estructurada completa de las entidades, tipos de datos y relaciones en formato JSON (`schema-graph.json`)[cite: 2, 5].
3. **`build.php`**: Un script ejecutable maestro que consolida la recreación de la base de datos, la inyección del esquema (`schema.sql`), los datos del sistema (`sys-data.sql`) y la ejecución de los generadores[cite: 2].

## Consecuencias

### Positivas
* **Fuente Única de Verdad**: La base de datos orienta la generación de la capa de modelos y la documentación[cite: 2, 5].
* **Sincronización Total**: El desarrollo de nuevos módulos o cambios en la base de datos se refleja instantáneamente con ejecutar `php build.php`[cite: 2].
* **Consumo de Metadatos**: El archivo `schema-graph.json` permite alimentar herramientas externas, agentes de IA y utilidades del sistema con el contexto actualizado del dominio[cite: 2, 5].

### Negativas
* Cambios manuales directos sobre los archivos dentro de `db/models/` corren el riesgo de ser sobrescritos al reejecutar el script de construcción si no se aplican extensiones orientadas a POO (clases heredadas o traits).
