# ADR-002: Uso de Eloquent ORM (Illuminate Database) fuera de Laravel

## Contexto
El desarrollo del backend requiere un nivel elevado de abstracción para la gestión de modelos, relaciones complejas entre entidades y consultas a la base de datos MariaDB/MySQL[cite: 3, 5]. Desarrollar un mapeador objeto-relacional (ORM) propio incrementaría la deuda técnica y el tiempo de desarrollo. Sin embargo, utilizar el framework Laravel completo añadía sobrecarga e innecesaria complejidad para la estructura nativa en PHP planteada[cite: 2, 3].

## Decisión
Se decide integrar `illuminate/database` (Capsule Manager) de Laravel de forma independiente mediante Composer[cite: 2, 3, 4]. Esto permite aprovechar las capacidades del ORM Eloquent dentro de un entorno PHP puro[cite: 2, 3].

Adicionalmente, se establece la convención arquitectónica obligatoria de ejecutar la inicialización global `Connection::boot()` previo a cualquier consulta a modelos en el sistema (por ejemplo, en el punto de entrada principal `index.php`)[cite: 3].

## Consecuencias

### Positivas
* **Productividad**: Aceleración en la definición de entidades y relaciones complejas (Foreign Keys, relaciones `belongsTo`, etc.)[cite: 3, 5].
* **Mantenibilidad**: Código de acceso a datos limpio, expresivo y basado en estándares PSR-4[cite: 3, 4].
* **Ligereza**: Mantiene una huella de memoria baja al no acoplar todo el ecosistema de un framework pesado.

### Negativas
* Necesidad de gestionar manualmente la inicialización y arranque de servicios de base de datos que el framework Laravel resolvería de forma implícita[cite: 3].
