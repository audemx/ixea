# ADR-012: Arquitectura operativa de módulos de aplicación

## Contexto
Los módulos de aplicación son los encargados de gestionar la lógica de negocio de cada funcionalidad del sistema. Por esta razón deben estar centralizados e integrados en cada nivel de arquitectura. El sistema operativo opera a través de los siguientes niveles de abstracción:

1. **Frontend**:  Interfaz de usuario que permite la interacción entre el usuario y el sistema. Se encarga de mostrar la información al usuario y recibir sus acciones.
    * **Menu:** Barra superior fija que contiene indicadores globales, usuario, widgets, búsqueda y notificaciones, además del menú principal del sistema y carga dinámicamente el menú de cada módulo de aplicación.
    * **Stages:** Espacio de trabajo dinámico multitarea que permite abrir e interactuar con múltiples aplicaciones de manera simultánea sin perder el contexto operativo.
    * **Launchpad:** Stage permanente de lanzamiento de aplicaciones. Se cargan automáticamente módulos permitidos por roles del usuario.
    * **Docker:** Indicador lateral de aplicaciones abiertas en stage. Permite hacer switch entre aplicaciones abiertas.
2. **Backend**: Gestiona las acciones del usuario, permisos, operaciones en base de datos, servicios, etc. Debe estar centralizado y ser el único encargado de la lógica de negocio.
3. **Database**: Almacena la información del sistema y del negocio de forma estructurada y persistente.

## Decisión


1. **Escenarios (`Stages`)**: Un espacio de trabajo dinámico multitarea que permite abrir e interactuar con múltiples aplicaciones de manera simultánea sin perder el contexto operativo[cite: 3].
2. **Estaciones (`Stations`)**: Un modo enfocado en un único proceso crítico (e.g., caja, comanda, cocina) para optimizar la velocidad y reducir errores operativos[cite: 3].

## Consecuencias

### Positivas
* **Flexibilidad Operativa**: Satisface tanto las necesidades de gestión administrativa compleja como la operación rápida en punto de venta[cite: 3].
* **Experiencia de Usuario Adaptativa**: Reduce la fatiga cognitiva al adecuar la UI/UX al rol específico del usuario[cite: 3].

### Negativas
* Mayor complejidad en la gestión del estado en el cliente (JavaScript ES6+) para coordinar el contexto de las aplicaciones abiertas en el modo `Stages`[cite: 3].
* Mantenimiento de vistas y estilos diferenciados para componentes compartidos entre ambos modos[cite: 3].
