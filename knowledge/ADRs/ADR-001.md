# ADR-001: Adopción de arquitectura híbrida Stages/Stations para el Frontend

## Contexto
El sistema operativo web IXEA EROS requiere adaptarse a múltiples contextos operativos dentro de la gestión empresarial (ERP/POS/CRM) y diferentes sectores comerciales como restaurantes y retail[cite: 3]. Los usuarios administrativos necesitan trabajar de forma multitarea con múltiples aplicaciones simultáneamente[cite: 3]. Por otro lado, los usuarios operativos (como vendedores, cajeros o meseros) requieren una interfaz de alta concentración, bajo nivel de distracción y rápida interacción[cite: 3].

## Decisión
Se decide implementar una arquitectura de interfaz multimodo basada en dos entornos diferenciados[cite: 3]:

1. **Escenarios (`Stages`)**: Un espacio de trabajo dinámico multitarea que permite abrir e interactuar con múltiples aplicaciones de manera simultánea sin perder el contexto operativo[cite: 3].
2. **Estaciones (`Stations`)**: Un modo enfocado en un único proceso crítico (e.g., caja, comanda, cocina) para optimizar la velocidad y reducir errores operativos[cite: 3].

## Consecuencias

### Positivas
* **Flexibilidad Operativa**: Satisface tanto las necesidades de gestión administrativa compleja como la operación rápida en punto de venta[cite: 3].
* **Experiencia de Usuario Adaptativa**: Reduce la fatiga cognitiva al adecuar la UI/UX al rol específico del usuario[cite: 3].

### Negativas
* Mayor complejidad en la gestión del estado en el cliente (JavaScript ES6+) para coordinar el contexto de las aplicaciones abiertas en el modo `Stages`[cite: 3].
* Mantenimiento de vistas y estilos diferenciados para componentes compartidos entre ambos modos[cite: 3].
