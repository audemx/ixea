# ADR-004: Aislamiento del Entorno de Desarrollo y Separación de Capas HTTP/App mediante Docker

## Contexto
Para garantizar la paridad entre los entornos de desarrollo y producción, así como prevenir el acceso público directo a archivos de lógica sensible del negocio (como clases del núcleo, conectores a bases de datos o configuraciones), se necesitaba una arquitectura de archivos estructurada y un entorno de ejecución aislado[cite: 1, 2].

## Decisión
Se implementa una arquitectura basada en contenedores Docker mediante `Dockerfile` y `docker-compose.yml`, acompañada por una estricta separación de carpetas[cite: 1, 2]:

1. **`src/public/`**: Único directorio expuesto públicamente a través del servidor web Apache (`http://localhost:8000`)[cite: 1, 2]. Contiene recursos estáticos, estilos CSS, assets e indexadores públicos[cite: 1].
2. **`src/app/`**: Directorio ubicado fuera de la raíz web del cliente o protegido contra acceso público, donde habitan las clases, configuraciones, conexiones a base de datos, modelos y dependencias de Composer (`composer.json`)[cite: 1, 2, 4].
3. **Contenedores Dedicados**: Separación explícita del servidor Web (Apache con PHP 8.x), servidor de base de datos (MariaDB) y administrador de BD (phpMyAdmin)[cite: 1, 2, 3].

## Consecuencias

### Positivas
* **Seguridad Estructural**: Imposibilidad de ejecutar scripts o acceder a archivos sensibles del backend (`.env`, `schema.sql`, `Connection.php`) de forma directa mediante peticiones HTTP[cite: 1].
* **Entorno Homogéneo**: Todo el equipo de desarrollo ejecuta la misma versión de PHP (8.2) y MariaDB/MySQL sin importar el sistema operativo host[cite: 2, 3, 4].
* **Facilidad Operativa**: Automatización del ciclo de vida del entorno mediante alias en la terminal (`ixea-up`, `ixea-down`, `ixea-build`)[cite: 2].

### Negativas
* Ligero consumo adicional de recursos de hardware en la máquina local para mantener en ejecución el motor de Docker.
